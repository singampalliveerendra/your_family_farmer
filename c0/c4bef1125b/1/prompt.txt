1. What is the Moderator?
The Moderator is a trusted local person — assigned by the GoGrameen founders — who manages the farmer-consumer ecosystem in a specific geographic zone. For the first 3 months, the founders themselves will act as the moderator for the Tadepalligudem zone.

Onboards new farmers in their zone (especially farmers who cannot use smartphones)
Reviews and approves farmer listings before they go live on the consumer page
Monitors supply vs demand and recruits farmers to fill gaps
Handles escalations — delivery delays, quality complaints, payment issues
Manages delivery agents — registers, monitors, activates/deactivates
Sets suggested price ranges per crop so new farmers price sensibly

ℹ  Route: /moderator (or /moderator/dashboard). Login required. Role = "moderator" in the Supabase profiles table. A moderator only sees data for their assigned zone.

2. Feature specifications
  Feature 1     Dashboard home
The first screen when the moderator logs in. Instant snapshot of zone health — stat cards, an alert strip, and quick-action buttons.

Screen contents
Header: moderator name, zone name, today's date
Alert strip: red if open escalations or pending approvals exist; amber if any crop is scarce; green if all is well
Six stat cards: Active farmers, Consumers, Orders this week, GMV this week, Open escalations (red if > 0), Pending approvals (amber if > 0)
Quick action buttons: "Onboard a farmer", "Review listings", "View escalations", "View reports"

Use Next.js router.push(). No API needed. Button 1 → /moderator/farmers/new. Button 2 → /moderator/listings. Button 3 → /moderator/escalations.

  Feature 3     Listing management
Every farmer listing goes through the moderator for approval before appearing on the consumer page. This keeps listing quality high and prevents pricing errors.

Screen contents
Three tabs: Pending approval (amber count badge), Active listings, Rejected
Each pending card: produce name, farmer, method, price, stock, BRIX, date submitted
Per card actions: Approve (green), Reject (coral — requires reason text), Edit before approving
On approve: status → available, consumer page shows listing, farmer gets WhatsApp
On reject: status → rejected, farmer gets WhatsApp with the rejection reason

Feature 4 — Supply vs demand: crop balance table and comparison bars
Developer tasks
Task ID
Task name
What to build
How (for a fresher)
MOD-4.1
Supply & demand data
Aggregate demand from intents and supply from active listings.
Two Supabase queries: (1) SELECT crop_name, SUM(quantity_kg) FROM demand_intents WHERE region_slug = zone GROUP BY crop_name. (2) SELECT name, SUM(stock_qty) FROM produce_listings WHERE status = "available" GROUP BY name. Merge in JS.
MOD-4.2
Status colour logic
Calculate status from supply and demand numbers.
In JS: if supply >= demand → "OK". Else if supply >= demand*0.5 → "Low". Else if supply < demand*0.5 → "Scarce". Else if supply > demand*1.5 → "Surplus". Apply Tailwind badge class.
MOD-4.3
Bar chart
Demand vs supply bars per crop using Chart.js.
new Chart(canvas, { type: "bar", data: { labels: cropNames, datasets: [{ label: "Demand", data: demandArray, backgroundColor: "#EF9F27" }, { label: "Supply", data: supplyArray, backgroundColor: "#4A8A2D" }] } })
MOD-4.4
Notify farmers button
WhatsApp message to all farmers in zone who grow the scarce crop.
POST /api/moderator/notify-scarce with { crop_name }. Query farmers in zone whose crops_raw ILIKE "%{crop_name}%". Build Twilio WhatsApp call for each.

Developer tasks
Task ID

What to build

MOD-9.1
Period toggle
Three buttons: This week / This month / Last month.
useState({ period: "week" }). Each button updates state. Compute startDate and endDate from the period value. Pass to all API calls.
MOD-9.2
KPI queries
Orders, GMV, avg order value, escalation resolution rate.
GET /api/moderator/reports?region=zone&from=DATE&to=DATE. SQL: SELECT COUNT(*) as orders, SUM(total_price) as gmv, AVG(total_price) as avg_order FROM orders WHERE created_at BETWEEN from AND to.
MOD-9.3
Top farmer & most popular crop
Who sold most and which crop moved most.
SELECT farmer_id, SUM(total_price) as gmv FROM orders GROUP BY farmer_id ORDER BY gmv DESC LIMIT 1. For crop: SELECT produce_name, COUNT(*) FROM order_items GROUP BY produce_name ORDER BY COUNT(*) DESC LIMIT 1.
MOD-9.4
PDF export
Download the current report as a PDF.
Add @media print CSS: hide sidebar and nav, show only the report content. Call window.print() when the Download button is tapped. Browser renders a printable PDF.

Run all of these in Supabase SQL editor before starting development.

3.1  New tables
delivery_agents
CREATE TABLE delivery_agents (
  id            uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  name          varchar(100) NOT NULL,
  phone         varchar(15) NOT NULL,
  aadhaar_hash  text,
  vehicle_type  text,
  delivery_area text,
  availability  text[],
  zone          varchar(60),
  active        boolean DEFAULT true,
  created_at    timestamptz DEFAULT now()
);

price_guidelines
CREATE TABLE price_guidelines (
  id           uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  crop_name    varchar(100) NOT NULL,
  region_slug  varchar(60) NOT NULL,
  min_price    numeric(8,2),
  max_price    numeric(8,2),
  unit         varchar(20) DEFAULT 'kg',
  updated_by   uuid REFERENCES moderators(id),
  updated_at   timestamptz DEFAULT now()
);

3.3  RLS policies
-- Moderators read only their own zone's farmers
CREATE POLICY "moderator_zone_farmers" ON farmers FOR SELECT
  USING (region_slug = (SELECT region_slug FROM profiles WHERE id = auth.uid()));

-- Moderators can update listings in their zone
CREATE POLICY "moderator_zone_listings" ON produce_listings FOR UPDATE
  USING (farmer_id IN (SELECT id FROM farmers WHERE region_slug =
    (SELECT region_slug FROM profiles WHERE id = auth.uid())));

  USING (region_slug = (SELECT region_slug FROM profiles WHERE id = auth.uid()));
